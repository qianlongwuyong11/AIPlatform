# AgentForge 扩展篇 · Stage 5 总纲

> Stage 5 = 主线（ch01-12，"能做"）之后的扩展设计篇：跟进 AI 前沿变化，规划如何把项目继续升级为更具生产韧性的 Multi-Agent 平台。

> 学法：**以三大优秀 Agent（Claude Code / OpenClaw / Hermes）为镜**，对照我们这个服务端多租户平台，逐章看"哪些直接用、哪些要改、哪些根本不适用"。

> **范围说明**：Stage 5 当前提供的是可用于方案推演和面试讲解的关键实现示例，覆盖接口、数据结构与核心流程；这些示例尚未合入 Java、Go 或 Python 的可运行工程，不代表已经完成生产落地。学习时应重点掌握为什么这样设计、关键链路如何运转，以及真正落地时还需要补哪些工程验证。

**面试表达边界**：可以说“我完成了主线工程，并针对生产化问题做过 Stage 5 的专项设计和关键代码推演”；可以继续讲接口约束、核心流程、异常边界和落地计划。不要声称 Stage 5 已经合入工程、完成联调、压测或线上验证，除非后续确实补齐了这些证据。

## 1. 部署语境前提（贯穿全篇的魂）

> 这是本篇最重要的一条认知：很多 Agent 教程把本机 dev-tool（Claude Code 这种）的做法直接搬，而我们是**服务端、多租户**的平台，照搬会出错。每章的选型都回到这张表。

| **维度** | **三大 Agent（本机 dev-tool）** | **AgentForge（我们，服务端平台）** |
| --- | --- | --- |
| **部署形态** | 多数本机、单用户 | **服务端、多租户、统一部署（类豆包）** |
| **工具** | 本地文件 / shell / git | 业务 API / 企业系统 / 知识库 / MCP |
| **沙盒语义** | 防 Agent 碰**开发者宿主机** | 防**租户间互窜** + 防打穿共享算力 |
| **记忆** | 本地文件 | 分布式 Redis / Milvus，**按租户**隔离 |
| **配置** | 本地配置文件 | **etcd 动态下发**，多实例广播 |
| **并发** | 单用户单会话 | 多租户、多会话、高并发 |

**每章都回答这一个问题**：三大 Agent 的某个设计，从"本机单用户"搬到"服务端多租户"——哪些直接用、哪些要改、哪些根本不适用？

## 2. 章节速览（11 章 + 2 附录）

**每章把项目哪块从 X 升级到 Y**（点进每章看完整内容）：

- **ch1 记忆**：对话历史往 Redis 一锅存 → 三层（热/归档/情景）+ 防污染

- **ch2 多租户**：基本没隔离、靠业务层自觉 → 5 级矩阵 + tenantId 贯穿全链路

- **ch3 权限**：扁平认证 + Agent 继承全权 → RBAC + 三层纵深 + Agent 作 NHI

- **ch4 资源控制**：只有一道令牌桶 → 四道闸（+Token 预算 + 熔断 + 活跃度超时）

- **ch5 Skill**：过滤没打通、无按需加载 → 渐进式披露 + 可见性裁剪 + 自动沉淀

- **ch6 工具沙盒**：零沙盒、进程内裸执行 → 三层防线 + ExecutionBackend

- **ch7 RAG**：基线纯稠密向量 → 平台集成层（检索质量走项目二 DeepRAG）

- **ch8 多 Agent**：已有工作流引擎，缺门禁/主动 → 默认单 Agent 门禁 + 主动 Agent

- **ch9 Gateway**：过滤器链已有，session 平面/fail-open → 层级 session key + 严格 fail-closed

- **ch10 错误处理**：调用级容错空白 → 错误分类 + 重试 + 降级 + 防假完成

- **ch11 MCP**：统一注册表已有，全量加载/凭证透传 → defer_loading + 凭证隔离

- **附录A**：漂移/压缩散在别章 → 目标重注入 + 决策 ADR + 五层压缩总图

- **附录B**：工具描述无校验 → Anthropic 五原则 + 注册强制校验

> 核心 1-8 章按"学员被拷打程度"排序；9-11 章补原本没专章的 Gateway / 错误处理 / MCP；两附录收束长任务可靠性与工具描述规范。

## 3. 全篇能力地图（面试前扫一眼）

> "部署语境前提"落到每一章的样子——每章和三大 Agent 的不同在哪。这张表随章节增长，将来加新章往这续一行就行。

| **章** | **核心设计** | **服务端独有维度（和三大 Agent 的不同）** |
| --- | --- | --- |
| **1 记忆** | 分布式分层 + 防污染 | 按租户隔离记忆 |
| **2 多租户** | 5 级矩阵 + Pool 模型 | **服务端独有，三大 Agent 不做** |
| **3 权限** | RBAC + 三层纵深 + 可逆性 | Agent = NHI，不继承人类全权 |
| **4 资源控制** | 四道闸 + 死循环兜底 | 公平性护栏（防 noisy neighbor） |
| **5 Skill** | 渐进式披露 + 可见性裁剪 | 沉淀质量门禁 + 来源签名 |
| **6 工具沙盒** | 三层防线 + ExecutionBackend | 防租户互窜（非防碰宿主） |
| **7 RAG 集成** | Lost-in-Middle + 热度 + 多租户 | 检索质量走【项目二 DeepRAG】；平台集成服务端独有 |
| **8 多 Agent** | 默认单 Agent 门禁 + 主动 Agent | bindings 路由 + 主动巡检 |
| **9 Gateway** | 控制平面 + 层级 session key + fail-closed | 服务端独有（本机无 Gateway） |
| **10 错误处理** | 错误分类 + 重试 + 熔断 + 降级 + 防假完成 | 级联隔离 / 续跑保多租户可用性 |
| **11 MCP** | defer_loading + 凭证隔离 + 统一注册表 | 凭证隔离（多租户 + 不可信代码） |

**贯穿全篇的四条共性**：① 护栏全在程序层（不靠 Prompt）② 按 tenantId 贯穿 ③ 声明式（etcd 动态下发）④ 用语言无关的设计契约配合关键实现示例讲清核心机制，Java、Go、Python 学员均可阅读。
