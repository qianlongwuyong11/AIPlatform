# 第 3 章 · 权限体系：RBAC + 工具三层纵深 + 可逆性

> **为什么有这章**：原项目认证扁平（API Key→userId，有的接口硬编码兜底能绕过）、工具调用零权限校验、Agent 直接继承登录用户的全权——prompt injection 一得手，Agent 就能"借"人类全权干跨租户的坏事，破坏性操作也没有第二道闸。这章补 **RBAC 四级 + 工具三层纵深 + 可逆性维度 + Agent 作 NHI 不继承全权**；对应学员反馈"权限隔离"。

## 这篇讲什么

权限体系要解决的问题是：**Agent 调工具的权力怎么控、破坏性操作怎么把关、prompt injection 会不会让 Agent"借权"干坏事**——现状是扁平 + 可绕过（API Key → userId、某些接口硬编码兜底、工具调用零权限校验），Agent 直接拿登录用户的全权跑。

为什么服务端要单拎出来讲：本机的 Claude Code / OpenClaw 里 Agent ≈ 用户自己，用自己的权理所当然；我们是服务端平台，Agent 代表平台调工具，是**非人类身份（NHI）**——一旦 prompt injection 得手，Agent "借"的是平台全权，能跨租户干坏事（OWASP Excessive Agency）。所以 Agent 绝不能继承人类全权，必须用 task-scoped 短期凭证。这是这章和本机工具最大的不同。

**核心模型：RBAC 打底 + 工具三层纵深 + 可逆性维度。** 请求进来先过角色校验，工具调用依次过三道闸，破坏性操作还要人批：

```Plaintext
请求 → AuthFilter(RBAC 四级：Owner/Admin/Developer/Viewer，无 token 不兜底)
        │  Agent 拿 task-scoped 短期凭证（NHI，不继承人类全权）
        ▼
工具三层纵深：① 白名单（角色绑最小集，未授权工具不进 LLM schema）
              ② 运行时 PEP（Agent 用 service identity）
              ③ 破坏性 HITL（富文本审批，irreversible 才触发）
```

**三个关键认知（想通这三个，这章就懂了）：**

- **护栏必须写在程序层，绝不靠 Prompt**：权限检查放模型层（Prompt 约束）能被 prompt injection 直接绕过，最弱；放框架层（程序逻辑）绕不过；放系统层（沙箱）物理隔离，最强。OpenClaw 六层级联设计健全但 default-open，等于把安全外包给最不懂安全的用户——反面教材。服务端必须 default-deny。

- **工具自带风险画像 + 分类器不看推理/结果**：每个工具自带 risk（READ/WRITE/EXEC）和 reversibility 标签，加新工具不改权限核心（开闭原则）。Claude Code 的 Auto Mode 分类器刻意只看"请求 + 工具调用"、不看模型推理文字和执行结果——防 prompt injection 用流畅解释说服分类器放行。这个信息边界是结构性防御，不是细节。

- **可逆性是比"操作类型"更稳的第一维度 + 审批即审计**：按"出错能不能回滚"切分（reversible 自动 / costly 确认 / irreversible 强制富文本审批），比按"读/写/执行"分类更稳。富文本审批携带动作/理由/不可逆性/替代方案/决策 5 字段——既是破坏性把关（是/否弹窗会退化成仪式，Claude Code 93% 批准率），又天然是审计记录：这 5 个字段落库就是一条完整的操作审计日志，不用另起一套审计系统。

> 这是这章的骨架。三层纵深具体怎么落、关键实现示例代码长什么样，往下看 §3.2 起。**细节是用来查的，不用全记**；先把上面这个模型和三个认知想清楚。

## 3.2 三大 Agent 的权限设计（重点：讲透）

### 3.2.1 核心问题：权限检查放在哪一层

所有工具调用都走同一条流水线，**权限检查插在哪一层**决定了能不能被绕过：

<!-- 画板未能抓取（请把画板滚动到可见区域后重试，或在飞书里另存为图片手动插入） -->

权限检查的三层位置（安全强度递增）：

```Plaintext
[模型层] 靠 Prompt 约束        → 能被 prompt injection 绕过（最弱）
[框架层] 靠程序逻辑拦截        → 绕不过（中）
[系统层] 靠沙箱隔离            → 物理隔离（最强）

→ 铁律：安全护栏必须写在程序层或系统层，绝不能只靠 Prompt。
```

### 3.2.2 OpenClaw —— 六层级联 + default-open（反面教材）

OpenClaw 的权限模型设计本身健全（六层级联），但**默认值致命**：

> 分类器**不看推理、不看结果**是刻意设计——防 prompt injection 通过工具返回值污染分类器判断。这个边界设计非常值得讲。

### 3.2.4 Hermes —— 模式匹配 + fail-closed + 容器跳过

Hermes 的危险命令审批 = 模式匹配危险检测 + 三种模式 + fail-closed：

```Plaintext
危险模式库检测：递归删除 / 权限修改 / sudo 使用 …

approvals:
   mode: manual   # manual（默认，手动确认）/ smart（AI 辅助）/ off（全自动 YOLO）
   timeout: 60    # 超时未响应 → 默认【拒绝】（fail-closed，不是放行）

关键：运行在 Docker/Modal 等容器后端时，危险命令审批【被跳过】
   → 因为容器本身就是安全边界，容器内破坏性命令影响不到宿主
   → "把安全下推到基础设施层"
```

| **框架** | **权限模型** | **默认值** | **自动化判断** |
| --- | --- | --- | --- |
| **OpenClaw** | 六层级联 | **default-open**（反面） | 无（靠用户配置） |
| **Claude Code** | 工具自带画像，三档 | 偏保守 | Auto Mode 两阶段分类器（不看推理/结果） |
| **Hermes** | 模式匹配 + 三模式 | manual + fail-closed | smart 模式（AI 辅助） |

### 3.2.5 可逆性：权限的第一维度

还有一个更本质的权限切分维度——**按"出错能不能回滚"分类**，这比"按操作类型"更稳：

```Plaintext
[可逆]   只读、查询、沙箱写      → 出错能回滚     → 自动放行
[有成本] 改代码、外部通信、改 DB  → 有副作用但可救 → 需确认
[不可逆] 删生产数据、财务/合同/医疗 → 回不来       → 强制人主导

→ 可逆性标签写在工具注册元数据里（不是临时判断）
```

**富文本审批 vs 是/否弹窗**（破坏性操作的把关）：

| **类型** | **问题** | **效果** |
| --- | --- | --- |
| **是/否弹窗** | 用户不看就点是 | 93%批准率 退化成仪式 |
| **富文本审批** | 动作+理由+不可逆性+替代方案+决策 | 让人真正介入 + 天然审计日志 |

## 3.3 选型：服务端多租户语境下的权限

> 关键差异：**三大 Agent 里，Agent ≈ 用户自己**（本机工具，用自己的权限）；**我们的 Agent 是服务端的非人类身份（NHI）**，代表平台调工具，**绝不能继承人类用户的全权**。

| **维度** | **本机 Agent 三大** | **服务端平台 AgentForge** |
| --- | --- | --- |
| **身份** | Agent=用户自己 | Agent=平台 NHI |
| **权限** | 继承用户全权 | task-scoped 短期凭证 |
| **injection后果** | 借用户自己的权 | 借平台全权 跨租户 |

**对应 OWASP LLM 风险**：

- **LLM01 Prompt Injection**：注入让 Agent 执行未授权操作 → 靠程序层权限 + 分类器不看结果

- **Excessive Agency**：Agent 权限过大 → 靠 NHI 最小权 + 工具三层纵深 + 破坏性 HITL

**选型结论**：

```Plaintext
RBAC 四级打底（Owner/Admin/Developer/Viewer）
   + 工具三层纵深：① 白名单（按角色绑最小集，未授权不进 LLM schema）
                   ② 运行时 PEP（Policy Enforcement Point，Agent 用 service identity）
                   ③ 破坏性操作 HITL interrupt 审批
   + 可逆性维度（reversible/costly/irreversible 标签）
   + 富文本审批 + 审计日志
   + Agent 不继承人类全权（NHI + task-scoped 凭证）
```

### 3.5.2 RBAC 四级 + AuthFilter（关键实现示例，修复可绕过）

```Java
// Java：AuthFilter 强制角色校验（不再有"无 token 兜底"）
public class AuthFilter implements GatewayFilter {
    @Override public Result check(Request req) {
        String token = req.getHeader("Authorization");
        if (token == null) return Result.deny("no token");   // ← 不再硬编码兜底放行
        User user = auth.verify(token);                       // 解出 userId + role + tenantId
        Role role = user.role;                                // OWNER/ADMIN/DEVELOPER/VIEWER
        if (!role.canInvoke(req.agentId)) return Result.deny("forbidden");
        return Result.allow(user);
    }
}
```

```Go
// Go：中间件强制校验
func AuthMiddleware(next Handler) Handler {
    return func(ctx *RequestContext) error {
        token := ctx.Token
        if token == "" { return ErrNoToken }                 // 不兜底
        user, err := auth.Verify(token)
        if err != nil || !user.Role.CanInvoke(ctx.AgentID) {
            return ErrForbidden
        }
        ctx.UserID, ctx.Role, ctx.TenantID = user.ID, user.Role, user.TenantID
        return next(ctx)
    }
}
```

```Python
async def auth_filter(request: Request, call_next: Callable) -> Response:
    # 不提供匿名兜底身份：没有 Bearer Token 就立即拒绝。
    token = request.headers.get("Authorization")
    if not token:
        raise HTTPException(status_code=401, detail="missing token")

    user = await auth.verify(token)
    if not user.role.can_invoke(request.path_params["agent_id"]):
        raise HTTPException(status_code=403, detail="forbidden")

    # 验证后的租户、用户和角色进入请求上下文，供所有下游策略复用。
    request.state.context = RequestContext.from_user(user, request)
    return await call_next(request)
```

| **设计点** | **方案** | **教学价值** |
| --- | --- | --- |
| **无 token 不兜底** | 直接 deny | 修复"硬编码放行"，认证不可绕过 |
| **RBAC 四级** | Owner/Admin/Developer/Viewer | 角色化访问控制基础 |
| **角色 × Agent** | canInvoke 校验 | 不是登录就能调所有 Agent |

### 3.5.3 工具三层纵深（关键实现示例）

```Java
// Java：工具注册时带风险画像 + 可逆性
public interface Tool {
    String name();
    RiskLevel risk();        // READ / WRITE / EXEC
    Reversibility reversibility();  // REVERSIBLE / COSTLY / IRREVERSIBLE
    ToolResult execute(Map<String,Object> args);
}

// ToolManager.execute 三层纵深
public ToolResult execute(RequestContext ctx, String toolName, Map args) {
    Tool tool = registry.get(toolName);
    // ① 白名单：角色没绑这个工具 → 不让 LLM 看到也调不了
    if (!rolePolicy.allows(ctx.role, toolName)) return ToolResult.deny("not in whitelist");
    // ② 运行时 PEP：Agent 用 service identity 校验（OPA/自研）
    if (!pep.allow(ctx.agentIdentity, toolName, args, ctx.tenantId)) return ToolResult.deny("policy denied");
    // ③ 破坏性 HITL：不可逆操作 → 富文本审批
    if (tool.reversibility() == IRREVERSIBLE) return hitl.requestApproval(ctx, tool, args);
    return tool.execute(args);
}
```

```Go
// Go：三层纵深
func (tm *ToolManager) Execute(ctx *RequestContext, name string, args map[string]any) ToolResult {
    t := tm.registry[name]
    if !rolePolicy.Allows(ctx.Role, name) { return Deny("not in whitelist") }
    if !tm.pep.Allow(ctx.AgentIdentity, name, args, ctx.TenantID) { return Deny("policy denied") }
    if t.Reversibility() == Irreversible { return tm.hitl.RequestApproval(ctx, t, args) }
    return t.Execute(args)
}
```

```Python
from typing import Any, Protocol

class Tool(Protocol):
    name: str
    reversibility: Reversibility

    async def execute(self, args: dict[str, Any]) -> ToolResult: ...

async def execute_tool(
    self, context: RequestContext, name: str, args: dict[str, Any]
) -> ToolResult:
    tool = self.registry[name]
    # ① 角色白名单：未授权工具不暴露，也不能绕过模型直接调用。
    if not self.role_policy.allows(context.role, name):
        return ToolResult.deny("not in whitelist")
    # ② 运行时策略：以 Agent 服务身份、参数和租户再次判定。
    if not await self.pep.allow(context.agent_identity, name, args, context.tenant_id):
        return ToolResult.deny("policy denied")
    # ③ 不可逆操作进入 HITL，审批前绝不执行真实工具。
    if tool.reversibility is Reversibility.IRREVERSIBLE:
        return await self.hitl.request_approval(context, tool, args)
    return await tool.execute(args)
```

## 小结

1. **Agent ≠ 用户**：服务端 Agent 是 NHI，不继承人类全权，用 task-scoped 最小权（核心差异）。

1. **工具三层纵深**：白名单不进 schema → 运行时 PEP → 破坏性 HITL。

1. **可逆性是第一维度**：reversible/costly/irreversible 标签，比操作类型更稳。

1. **权限写程序层**：不靠 Prompt；分类器不看推理/结果防污染。

1. **富文本审批 = 审计日志**：破坏性操作让人真正介入，留痕合规。
